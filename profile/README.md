## Why Firecrawl?

AI agents need clean, current web context to do real work: research, deep research, answering questions with live sources, monitoring, competitive intelligence, dataset building, enrichment, KYC, and signup pre-fill. Every step is hard. Pages are noisy, sites are dynamic, PDFs are messy, scrapers break.

Firecrawl is how AI agents turn the live web into something they can use:

**Find → Extract → Clean → Use**

Search is the front door. Scrape and Parse turn sources into clean context. Interact handles dynamic pages. Crawl and Map go deeper. The API is how teams build with Firecrawl in production. MCP, CLI, and Skills bring it into AI agent workflows.

## What Firecrawl does

| Endpoint | Job |
| --- | --- |
| **Search** | Find fresh, relevant sources from the live web in one call. Same call can scrape them. |
| **Scrape** | Turn any URL into clean Markdown or structured JSON. Works on JS-heavy pages, anti-bot, and geo-sensitive sites. |
| **Parse** | Convert PDFs and documents into usable text. |
| **Crawl** | Walk a site to build a corpus. |
| **Map** | Discover site structure fast. |
| **Interact** | Click, scroll, fill, log in, wait. For when Scrape isn't enough. |

One API, one output format, one compliance posture. Token-efficient Markdown by default, with headers, footers, and ads stripped. Plus JSON extraction with schemas, summary mode, highlight mode, and question mode.

## Built for production

- **Compliance-grade by default.** ZDR, DPA, US data residency, SOC 2 Type 2. Built for buyers who can't store payloads.
- **Sub-3-second scrape on real-world pages.** Latency matters at every step in the AI agent loop, not just discovery.
- **Replaces the multi-vendor stack.** Teams consolidate from Puppeteer, Playwright, Bright Data, Zyte, SerpAPI, and Exa onto a single Firecrawl API.
- **Direct support and shared Slack.** Every enterprise pilot ships with a named success engineer.
